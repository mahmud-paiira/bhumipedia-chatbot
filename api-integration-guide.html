1. Overview & concepts

The API exposes a single question-answering operation. You send a natural-language question (Bengali or English) and receive the best matching answer from a dataset built from the iLKMS land-law database. The server reuses the exact same extraction pipeline and scoring logic as the browser client, so responses match the offline build.

  • Dataset. Built once at server start from the six iLKMS tables and held in memory.
  • Language. Pass lang=bn (default) or lang=en for language-aware routing and small talk.
  • Answer types. Every response is tagged with a type: data, small, none, or doc_blocked.
  • Stateless. No sessions or cookies; each request is independent.

3. GET /api/search

Returns the best answer for a question.

Query parameters

NameRequiredDefaultDescription
qYes—The user's question (URL-encoded UTF-8). Empty ⇒ 400.
langNobnbn or en; affects small-talk text and template routing.

Example request

GET /api/search?q=%E0%A6%A8%E0%A6%BE%E0%A6%AE%E0%A6%9C%E0%A6%BE%E0%A6%B0%E0%A6%BF%20%E0%A6%AB%E0%A6%BF&lang=bn
# decodes to: q=নামজারি ফি

4. Response types & examples

All responses are JSON objects. The type field determines which other fields are present.

data A dataset answer was found

{
  "type": "data",
  "entry": {
    "q": "নামজারি ফি",
    "a": "**সংক্ষেপে:**\n• নির্ধারিত ফি ছাড়া এক টাকাও নেওয়া যাবে না।\n• …",
    "more": "…optional extended text…",
    "t": 0
  },
  "score": 1000,
  "offline": { "dataset": 46853, "rows": { "acts_acts": 349, "…": 0 } }
}
  • entry.q — the matched canonical question.
  • entry.a — the answer (may contain **bold** and • bullets / numbered lines).
  • entry.more — present only when a longer "more details" text exists.
  • entry.t — 1 if the entry is a template (act-level) question, else 0/absent.
  • score — match confidence; 1000 means an exact normalized match.

small Small talk / greeting

{
  "type": "small",
  "text": "ওয়ালাইকুম আসসালাম! 🌿 ভূমি সংক্রান্ত কী জানতে চান?",
  "offline": { "dataset": 46853, "rows": { "…": 0 } }
}

Detected greetings, name/help/thanks/goodbye intents. Return text directly.

none No confident answer

{
  "type": "none",
  "suggestions": ["খতিয়ান কি?", "নামজারি কীভাবে করবো?", "ভূমি উন্নয়ন খাজনা আইন, ২০২৩"],
  "offline": { "dataset": 46853, "rows": { "…": 0 } }
}

Render a friendly "not found" message and offer the suggested questions as clickable chips.

doc_blocked Template match blocked (use document search)

{
  "type": "doc_blocked",
  "query": "ভূমি সংস্কার আইন, ২০২৩",
  "offline": { "dataset": 46853, "rows": { "…": 0 } }
}
Client-side handling. The bundled app.js responds to doc_blocked by falling back to its local document search (docs.js) and rendering a quoted document excerpt. If you integrate the API directly, treat doc_blocked as "no dataset answer; try your own document search or show suggestions."

  • error — null when healthy; otherwise no_connection, load_failed, or empty_dataset.

Use /api/health for readiness/liveness probes; /api/stats for monitoring dashboards.

7. Errors & status codes

StatusBodyMeaning
200answer objectSuccess (including type=none)
400{"error":"missing 'q' param"}q missing or blank
404{"error":"not found"}Unknown path
500{"error":"…"}Unexpected server error
Network failure is not an HTTP error. If the API process is down, the request fails at the transport layer. Your client should catch that and fall back to the bundled data.js (as app.js does) or show an offline message.

8. CORS

Every response includes:

Access-Control-Allow-Origin: *
Access-Control-Allow-Methods: GET, OPTIONS
Access-Control-Allow-Headers: Content-Type

OPTIONS pre-flight requests receive 200 {"ok":true}. To restrict origins, edit the Access-Control-Allow-Origin value in server.py (_send()). Serving the UI from the same origin as the API avoids CORS entirely.

9. Integrating the bundled UI (app.js)

The client is already wired for API-first with offline fallback. To enable it, set the base URL in index.html before app.js loads:

<script>window.__BHUMI_API__ = "http://127.0.0.1:8790";</script>

Behaviour in app.js:

  1. If __BHUMI_API__ is empty ⇒ always use the bundled dataset.
  2. Otherwise respondLive() calls /api/search?q=…&lang=… with a 4-second timeout.
  3. On type=data it renders entry.a and appends a local document citation when one scores high.
  4. On type=small / type=none it renders the text / suggestions.
  5. On any network error or unexpected payload it sets LIVE_DOWN = true and falls back to the local findAnswer() for the rest of the session.
Version bump. After editing app.js, bump the ?v= query on the script tags in index.html to defeat browser caching.

10.2 JavaScript (browser / Node 18+)

async function ask(q, lang = "bn") {
  const url = `http://127.0.0.1:8790/api/search?q=${encodeURIComponent(q)}&lang=${lang}`;
  const res = await fetch(url);
  if (!res.ok) throw new Error("HTTP " + res.status);
  const d = await res.json();
  switch (d.type) {
    case "data":  return d.entry.a;
    case "small": return d.text;
    case "none":  return "No answer. Try: " + d.suggestions.join(", ");
    case "doc_blocked": return "No dataset answer; try document search.";
    default: throw new Error("bad payload");
  }
}

ask("নামজারি ফি").then(console.log).catch(console.error);

10.3 Python

import json, urllib.parse, urllib.request

def ask(q, lang="bn", base="http://127.0.0.1:8790"):
    url = base + "/api/search?" + urllib.parse.urlencode({"q": q, "lang": lang})
    with urllib.request.urlopen(url, timeout=10) as r:
        d = json.loads(r.read().decode("utf-8"))
    if d["type"] == "data":
        return d["entry"]["a"]
    if d["type"] == "small":
        return d["text"]
    if d["type"] == "none":
        return "No answer. Suggestions: " + ", ".join(d["suggestions"])
    return "No dataset answer."

print(ask("খতিয়ান কি?"))

10.4 PHP

<?php
function ask($q, $lang = 'bn', $base = 'http://127.0.0.1:8790') {
    $url = $base . '/api/search?' . http_build_query(['q' => $q, 'lang' => $lang]);
    $raw = file_get_contents($url);
    if ($raw === false) return 'offline';
    $d = json_decode($raw, true);
    if ($d['type'] === 'data')  return $d['entry']['a'];
    if ($d['type'] === 'small') return $d['text'];
    if ($d['type'] === 'none')  return 'Try: ' . implode(', ', $d['suggestions']);
    return 'No dataset answer.';
}
echo ask('নামজারি কীভাবে করবো?');

11. How answers are chosen

  • Normalization. Text is lower-cased, punctuation stripped, digits mapped to Bengali, and common spelling variants folded (e.g. ী→ি, ষ→স, শ→স, ভুমি→জমি).
  • Scoring. Weighted token overlap (longer tokens weigh more) with prefix partial credit; an exact normalized match scores 1000.
  • Threshold. A dataset answer is returned only at/above the confidence threshold (70); otherwise document search, small talk, or type=none suggestions are returned.
  • Tie-break. Equal scores prefer the most concise, lexically closest question.
  • Templates. Act-level template questions require an intent word (e.g. fee, how, apply) before being served, otherwise the server reports doc_blocked.

12. Best practices

  • Always handle transport failure and fall back to data.js for uninterrupted service.
  • URL-encode q (Bengali is multi-byte UTF-8).
  • Set a client timeout (the bundled client uses 4 s).
  • Cache responses for identical questions where appropriate; answers change only on server restart/DB update.
  • Probe /api/health for readiness; restart the server to refresh the dataset.
  • Keep the API internal behind your gateway; it has no authentication.
  • Respect UTF-8 end to end (headers, database client encoding, proxy).

1. Architecture & deployment modes

The chatbot is a browser app (index.html + data.js + docs.js + app.js) that answers land-law questions. Answers are produced by a single Q&A pipeline (build_db.extract_db()) which can be fed either from a static SQL export or from a live database. The browser can therefore operate in two modes:

ModeData sourceComponentsUse when
AStatic / offline data.js + docs.js bundled at build time Any static web server (or file://) No network/DB access; frozen approved snapshot; lowest cost
BLive API Live iLKMS PostgreSQL via server.py server.py + db_source.py + scorer.py + static files Answers must reflect live updates while still serving the curated snapshot offline
Graceful degradation. In Mode B the browser calls /api/search first. If the API or database is unreachable, it automatically falls back to the bundled data.js. The API server itself also keeps serving /api/health even when the database is down.

2. Prerequisites

2.1 Server host (Mode B)

  • Python 3.10+ (tested on 3.12.10).
  • Python packages: psycopg2-binary (or psycopg2) and python-dotenv. server.py uses only the standard library otherwise (no Flask required).
  • Network access from the host to the PostgreSQL instance (default port 5432).
  • A PostgreSQL role with read-only access to the six iLKMS tables (recommended).
pip install psycopg2-binary python-dotenv

2.2 Build host (Mode A, optional)

  • Node.js 18+ (tested on v24.12.0) — only for running test.js / test_samples.js.
  • The SQL export file in the project root.
Windows console note. The Python build scripts re-wrap stdout as UTF-8 because Bengali text breaks the legacy cp1252 console. If you see UnicodeEncodeError, run with set PYTHONUTF8=1 or chcp 65001.

4. Mode A — Static / offline deployment

  1. Ensure data.js, docs.js, app.js and index.html are present in the same directory.
  2. Serve the directory with any static web server. For a quick local check: 
    # Python (recommended over file:// so localStorage & fetch work consistently)
python -m http.server 8080
# then open http://127.0.0.1:8080/
  3. Leave window.__BHUMI_API__ = ""; in index.html (default). The app uses the bundled dataset.
Cache busting. Static asset URLs use a version query (?v=6). After rebuilding data.js or docs.js, bump the v number in index.html so browsers reload the new file.

5. Mode B — Live API deployment

Step 1 — Copy the environment template
copy .env.example .env      # Windows
cp .env.example .env        # Linux/macOS
Step 2 — Set the database connection

Edit .env and set DATABASE_URL (see section 6). Use a read-only role where possible.

Step 3 — Verify connectivity
python -c "import db_source; tb=db_source.load_tables_from_db(); print({k:len(v['rows']) for k,v in tb.items()})"

Expected output lists the six tables with their row counts. If it prints an error, see section 11.

Step 4 — Start the API server
python server.py
# [server] live dataset ready: 46853 entries
# [server] listening on http://127.0.0.1:8790
Step 5 — Point the UI at the API

In index.html, set the base URL (no trailing slash):

window.__BHUMI_API__ = "http://127.0.0.1:8790";
Step 6 — Verify end to end
curl "http://127.0.0.1:8790/api/health"
curl "http://127.0.0.1:8790/api/search?q=%E0%A6%96%E0%A6%A4%E0%A6%BF%E0%A6%AF%E0%A6%BE%E0%A6%A8%20%E0%A6%95%E0%A6%BF%3F&lang=bn"
Dataset refresh. The dataset is built once at server start. Restart server.py after the source database changes to pick up new content. Building the live dataset from the same export yields the same answers as the bundled data.js.

6. Configuration (.env)

VariableDefaultDescription
DATABASE_URLpostgresql://localhost/iLKMSpsycopg2 DSN. Accepts a URL or keyword string.
BHUMI_HOST127.0.0.1Bind address. Use 0.0.0.0 to accept external connections.
BHUMI_PORT8790Listening port.

Connection string examples

# URL form
DATABASE_URL=postgresql://ilkms_ro:secret@10.0.0.5:5432/iLKMS

# keyword form (useful for special characters in the password)
DATABASE_URL=host=10.0.0.5 port=5432 dbname=iLKMS user=ilkms_ro password=secret sslmode=require
Never commit .env. Keep it out of version control and restrict file permissions (chmod 600 .env on Linux). Use a dedicated read-only database role.

7. Running the server

7.1 Foreground (development)

python server.py

7.2 Background (Windows PowerShell)

Start-Process -FilePath python -ArgumentList "server.py" -WorkingDirectory "C:\path\to\Chatbot" -WindowStyle Hidden -RedirectStandardOutput "srv.log" -RedirectStandardError "srv_err.log"

7.3 Background (Linux)

nohup python server.py > srv.log 2>&1 &
Reverse proxy tip. For production, bind to 127.0.0.1 and let nginx terminate TLS and forward to 127.0.0.1:8790 (section 8.2).

8. Production hardening

8.1 Run as a service (Linux — systemd)

# /etc/systemd/system/bhumi-api.service
[Unit]
Description=Bhumi Bondhu Chatbot API
After=network.target postgresql.service

[Service]
WorkingDirectory=/opt/bhumi-chatbot
EnvironmentFile=/opt/bhumi-chatbot/.env
ExecStart=/usr/bin/python3 server.py
Restart=always
RestartSec=3
User=www-data
Group=www-data

[Install]
WantedBy=multi-user.target
sudo systemctl daemon-reload
sudo systemctl enable --now bhumi-api
sudo systemctl status bhumi-api

8.2 Run as a service (Windows — Task Scheduler or NSSM)

# NSSM example
nssm install BhumiApi "C:\Python312\python.exe" "C:\path\to\Chatbot\server.py"
nssm set BhumiApi AppDirectory "C:\path\to\Chatbot"
nssm set BhumiApi AppEnvironmentExtra DATABASE_URL=postgresql://ilkms_ro:secret@10.0.0.5:5432/iLKMS
nssm start BhumiApi

8.3 Reverse proxy (nginx)

server {
    listen 443 ssl;
    server_name bhumichat.example.gov.bd;

    ssl_certificate     /etc/ssl/certs/bhumi.crt;
    ssl_certificate_key /etc/ssl/private/bhumi.key;

    root /opt/bhumi-chatbot/www;   # index.html, data.js, docs.js, app.js
    index index.html;

    location /api/ {
        proxy_pass http://127.0.0.1:8790;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }
}
CORS. The API sends Access-Control-Allow-Origin: * and handles OPTIONS pre-flight. If you serve the UI from the same origin as the API (recommended, as in the nginx config above), CORS is not exercised at all. To restrict origins, edit the header value in server.py (_send()).

8.4 Security recommendations

  • Use a read-only PostgreSQL role; the server never writes.
  • Prefer TLS to the database (sslmode=require or stricter).
  • Place the API behind the reverse proxy / firewall; do not expose port 8790 publicly.
  • Keep .env out of the web root and out of version control.
  • Consider a request timeout / rate limit at the proxy layer.

9. Rebuilding the offline dataset

Run these from the project root, in order:

python extract_pdfs.py     # optional: layer text from the curated PDFs into pdf_text/
python build_data.py       # writes data.js  (uses the SQL export + pdf_source)
python build_docs.py       # writes docs.js  (act / document text for document search)

Then bump the asset version in index.html:

<script src="data.js?v=7"></script>
<script src="docs.js?v=7"></script>
<script src="app.js?v=7"></script>

Verify

node test.js            # core answer tests
node test_samples.js    # curated sample questions
Mode B parity. The live dataset is built from the same pipeline. The only expected difference is which near-duplicate question variant wins de-duplication; answers to real queries are identical.

10. Health checks & monitoring

EndpointPurposeHealthy response
GET /api/healthDB connectivity + dataset state{"ok":true, "dataset":>0, "error":null}
GET /api/statsDataset size + per-table row counts{"dataset":N, "rows":{...}, "error":null}
# simple uptime check
curl -fsS http://127.0.0.1:8790/api/health || echo "API DOWN"

The error field is null when healthy, otherwise one of no_connection, load_failed, or empty_dataset.

11. Troubleshooting

SymptomLikely causeFix
connect failed: … password authentication failedBad credentials in DATABASE_URLVerify user/password/host/port; test with psql.
column "is_draft" does not existQuerying a table whose schema differs from the exportUse the supported iLKMS schema / the six listed tables.
live DB unavailable (load_failed)Network/SSL/role permissionsCheck pg_hba.conf, sslmode, and grants.

CORS error in browser consoleCross-origin API without allowed headerServe UI and API from the same origin, or allow the origin.
Bengali renders as boxes / mojibakeConsole/file encodingUse UTF-8; on Windows run chcp 65001 or set PYTHONUTF8=1.
Stale answers after DB updateDataset cached at startupRestart server.py (or schedule a restart).
Port already in useAnother process on 8790Change BHUMI_PORT and update the UI URL.

12. Go-live checklist

  • ☐ .env created with a read-only DATABASE_URL; file not in version control.
  • ☐ python db_source.py lists all six tables with rows.
  • ☐ python server.py reports "live dataset ready".
  • ☐ /api/health returns ok:true and a non-zero dataset.
  • ☐ window.__BHUMI_API__ set to the API base URL.
  • ☐ UI answers correctly with the API up, and falls back gracefully with the API down.
  • ☐ Service auto-restart configured (systemd / NSSM / Task Scheduler).
  • ☐ Reverse proxy + TLS in place; API port not publicly exposed.
  • ☐ Offline build re-verified with node test.js and node test_samples.js.
